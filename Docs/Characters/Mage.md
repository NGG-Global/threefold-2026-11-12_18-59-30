# The Mage character

The playable Mage now has a rigged, animated humanoid body instead of the grey capsule.

**This is an intermediate character.** It gives the Mage a real skeleton, its movement and combat animations and a
readable adventurer silhouette, but its body is a mannequin from an animation library, and its
look does not yet meet the art bible (`Docs/ArtBible.md`). It is meant to be replaced by a
designed model; nothing in gameplay depends on it.

## What it is

| Part | Description |
| --- | --- |
| Body | The mannequin from Quaternius' Universal Animation Library (CC0): 65-bone humanoid rig, 1.83 m tall |
| Clothing | Slate-blue tunic, umber trousers, leather bracers, dark gloves, knee boots. Painted onto the body by region |
| Gear | Terracotta hood, shoulder mantle and short back cloak; belt with brass buckle and two pouches |
| Magical motifs | A glowing crystal on the mantle's clasp and a glowing rune band on the left (casting) wrist |
| Animations | Movement and traversal: Idle, Walk, Jog, Sprint, JumpStart, JumpLoop (fall), JumpLand, SpellShoot, ClimbUp, Hang (posed in code). Combat: 19 library clips for the disciplines' stances, strikes, charges, block, stagger, aerial attack and defeat (`Docs/CombatAnimationArchitecture.md`, listed in `Docs/AssetInventory.md`) |
| Size | About 15,600 triangles, one skinned mesh, nine materials, 41 animation clips, 14.7 MB file (4.0 MB before the combat clips; 10.5 MB before the martial styles, `Docs/MartialStyles.md`) |

Colours come from the art bible's provisional palette families: slate blue, dark umber,
weathered terracotta, warm leather and a restrained brass.

## How it is made

Everything is generated by code from free sources and can be rebuilt with one command.

1. `Tools/blender/build_mage.py` (Blender 4) reads the library files in
   `Tools/blender/sources/`, dresses the body, builds the gear around the skeleton, keeps 28
   animations (nine for movement and traversal, 19 for combat), poses Hang, and writes
   `Assets/Threefold/Art/Characters/Mage/Mage.fbx`.
   It can also render the preview images above.
2. In Unity, `CharacterModelPostprocessor` imports every model in `Assets/Threefold/Art/Characters`
   as Humanoid, names the clips, marks the loops and keeps the animations in place. No Inspector work.
3. `MageCharacterSetup` generates the materials, the Animator Controller, an upper-body mask and a
   `MageVisual` prefab in `Assets/Threefold/Generated/Characters/Mage`, puts the prefab under the
   Mage, hides the capsule and connects the animation driver.

Step 3 runs inside **Threefold > Setup > Fantasy Playground**, **Threefold > Setup > Mage
Prototype**, and the automated Android build. Nothing has to be run separately.

To rebuild the model after changing the script:

```
blender -b --factory-startup --python Tools/blender/build_mage.py -- \
  Tools/blender/sources/quaternius-ual1/UAL1_Standard.fbx \
  Tools/blender/sources/quaternius-ual2/UAL2_Standard.fbx \
  Assets/Threefold/Art/Characters/Mage/Mage.fbx Docs/Characters/images
```

Claude Code can run this in a cloud session; Blender is installed there from Ubuntu's packages.

After a rebuild, compare it with the previous file, so a change touches only what it meant to:

```
blender -b --factory-startup --python Tools/blender/compare_mage.py -- <previous Mage.fbx> \
  Assets/Threefold/Art/Characters/Mage/Mage.fbx
```

It fails if the skeleton, mesh or materials differ, or if any clip both files share has moved a bone
by more than 1 mm.

## How it moves

`CharacterAnimationDriver` on the Mage reads the movement and combat state and sets these
Animator parameters. Gameplay never reads the Animator.

| Parameter | From | Drives |
| --- | --- | --- |
| Speed | Horizontal speed in m/s | Idle (0), Walk (1.5), Jog (4, normal movement), Sprint (7) |
| Grounded | Ground contact | Falling and landing |
| VerticalSpeed | Vertical speed | Falling only once really falling, not on steps |
| Jump | The motor's jump event | JumpStart, then the fall loop |
| Cast | A successful cast | SpellShoot on the upper body, so the Mage can cast while running. While the combat animation director plays the disciplines (`Docs/CombatAnimationArchitecture.md`), it plays each discipline's own release instead and this layer is silent |

The Animator applies no root motion: the CharacterController moves the character, the animations
only show it. The Mage turns to face its aim when casting, as before.

## Replacing the model later

Put a new Humanoid FBX in `Assets/Threefold/Art/Characters/Mage/` and point
`CharacterModelPostprocessor.MageModelPath` at it, or overwrite `Mage.fbx`. Then delete
`Assets/Threefold/Generated/Characters/Mage` and the Mage's `MageVisual` child and run the setup.
Movement, camera, combat and input do not change. Any Humanoid rig works with the same Animator,
because Unity retargets the animations.

## Known limitations

- **Mannequin body.** There is no face, no hair and no hands beyond mitten-like fists. The art
  bible asks for believable faces and expressive features; this body cannot provide them.
- **Not yet painterly.** Materials are flat colours with low gloss. Hand-painted textures and
  linework are not implemented; the art bible lists those techniques as still to be proven in a
  prototype scene.
- **Rigid clothing.** The hood, mantle and cloak are fixed to the spine and head. They do not
  sway, and an arm raised forward can pass through the mantle's edge.
- **Cast hand.** The cast animation raises the left hand, and bolts leave from the chest. A
  hand-held cast point is a later improvement.
- **No turn animations.** Hit, block and death clips are now in the model for the combat animations;
  they are generic library clips, not designed for the Mage.

## Towards the real character

Quaternius publishes two free CC0 packs built for this exact rig: **Universal Base Characters**
(bodies with faces and 20 hairstyles) and **Modular Character Outfits - Fantasy** (12 outfits, 62
parts, including robes, cloaks and hoods). Both are downloaded through itch.io's pay-what-you-want
page, which needs a person to click through. Uploading their free "Standard" downloads to Claude
Code would let the same script build a Mage with a real face and designed clothing, with no change
to the Unity side.

## Executive summary

Three Asset Store packs are installed under `Assets/` (committed in `41d0d42`):

1. **Free Slash VFX** — URP Shader Graph mesh slashes, impacts, elemental projectiles  
2. **Hovl Studio / Magic Effects FREE** — broad combat library (slashes, hits, shields, AoE, sparks, smoke) on **Built-in** particle shaders  
3. **Vefects Free Fire VFX URP** — looping fire / floor fire with custom URP Amplify shaders  

Existing discipline combat already has a clean presentation hook (`DisciplineFeedback` + `DisciplinePresentation` on each `DisciplineDefinition`) and temporary SoftGlow particle bursts generated by `DisciplineSetup`. Melee timing is **data clocks** (`startupSeconds`), not Animation Events. The Mage has locomotion + one cast gesture (`SpellShoot`); **no melee animations** and **no hand/foot VFX sockets**.

**Best immediate use:** adapt Free Slash (URP-native mesh ribbons) for Arcane and Flame melee; rematerial Hovl pieces for Aegis force / shield / pulse; strip and restyle Vefects `_Simple` fires for environmental burn loops. Do **not** wire stock pack prefabs into gameplay paths — duplicate into Threefold-owned adapted prefabs, desaturate HDR colours, drop lights/collision/distortion, and keep particle budgets near the existing 6–18 guideline.

**Recommended first vertical slice:** Arcane melee step 1 — adapted slash trail during start-up + adapted impact on land — through existing `SwingStarted` / `SwingLanded` events.

**Blockers before shipping visuals:** Hovl Built-in → URP material remap; Free Slash HDR intensity and Point Lights; Vefects missing material GUIDs + heat-haze vs `m_RequireOpaqueTexture: 0`; LFS textures must be pulled on the laptop; no melee anims for hand-following ribbons yet.

## D. Animation integration

> **Update, 15 November 2026.** The combat animation sprint added melee, charge, block and reaction
> clips, hand information per slot, and timing cues anchored to the combat rules (hit window,
> contact, release, recovery, cancellation) that effects can use instead of Animation Events. See
> `Docs/CombatAnimationArchitecture.md`. The table below describes the state before that change.

### D.1 What exists today (Verified)

| Piece | State |
| --- | --- |
| Movement pack | Quaternius Universal Animation Library (CC0), baked into `Assets/Threefold/Art/Characters/Mage/Mage.fbx` via `Tools/blender/build_mage.py` |
| Clips | Idle, Walk, Jog, Sprint, JumpStart, JumpLoop, JumpLand, Hang (posed), ClimbUp, SpellShoot |
| Animator | Generated `MageAnimator.controller` (laptop): locomotion + upper-body Cast layer; **no Melee/Block/Hit states** |
| Driver | `CharacterAnimationDriver` — gameplay writes Animator; never reads clip times |
| Melee timing | `MeleeComboMachine` clocks: hit lands when `startupSeconds` elapses (instant `AreaStrike`) |
| VFX timing | `DisciplineFeedback`: sweep on `SwingStarted`; impacts on `SwingLanded`; release on `AbilityCaster.CastSucceeded` |
| Cast origin | `AbilityCaster` castPoint or chest offset `(0, 1.25, 0)` — not hands |
| Animation Events | **None** for combat |

### D.2 Proposed sync model (without changing combat rules)

Keep **combat resolution** on data clocks. Drive **presentation** from the same combat events already raised. Do not invent parallel timers that can desync from hits.

| Moment | Combat event (source of truth) | VFX action |
| --- | --- | --- |
| Swing start | `DisciplineCombat.SwingStarted` | Spawn discipline slash/trail oriented to `swing.Direction`; optional hand attach if sockets exist; existing ground sweep remains |
| Swing land | `SwingLanded` | Impact at each `LastStruck` AimPoint; stop/fade hand trail |
| Swing interrupt | `SwingInterrupted` *(wire if not already for FX)* | Stop emission, return looping charge FX to pool |
| Charge begin | `ChargeBegan` | Hand/forearm charge loop; intensity from charge 0–1 |
| Charge cancel / interrupt | `ChargeEnded` (cancelled) | Hard stop — no release burst |
| Charge release | `CastSucceeded` | Release burst at origin; projectile/area FX from ability assets |
| Projectile impact | `Projectile.Impact` | Prefab on `ImpactEffect` reference |
| Block / deflect | `PlayerGuard.Blocked` / `StatusKind.Deflected` | Shield flash / spark |
| Burn / push | `CombatEvents.Status` | Existing Embers / PushDust hooks |

### D.3 Hand / foot attachments (proposal)

1. Add empty sockets under Mage visual (Editor command under `Threefold/`): `Vfx_Hand_L`, `Vfx_Hand_R`, `Vfx_Foot_L`, `Vfx_Foot_R`, optionally `Vfx_Chest`. Prefer Humanoid bone follow (`HumanBodyBones.LeftHand` / `RightHand`) rather than hand-authored hierarchy edits in the FBX.  
2. Parent **local-space** charge/trail FX to sockets.  
3. Spawn **world-space** impacts, waves, pulses, and residual embers (unparented).  
4. Attack trails: local during swing; detach-or-stop on interrupt so they do not follow a cancelled pose.

**Assumption:** Quaternius mannequin hands are mitt-like (`Docs/Characters/Mage.md`); ribbons should read from forearm/wrist, not finger tips.

### D.4 Animation Events vs clocks

| Approach | When to use |
| --- | --- |
| **Keep clocks (recommended now)** | Until real melee clips exist; events already match hit resolution |
| **Animation Events later** | When dedicated melee anims are authored; events should call into the same presentation API, or retarget `startupSeconds` to clip hit frames so rules and visuals stay aligned |
| **Avoid** | Independent `Invoke` delays in feedback code — duplicates and interrupt bugs |

### D.5 Interrupt / duplicate safety (proposal)

- One active swing FX token per character; new swing replaces or refuses until previous one-shot finishes.  
- Charge loops use a single instance; `OnDisable` / cancel clears it.  
- Prefer one-shot `Play()` bursts over looping for melee.  
- Pool caps already exist (`MaxImpacts` 10, etc.); keep them.  
- Adapted prefabs should use `PooledEffect` (or extend it for “stop loops”) so lifetime returns to `Pools`.

### D.6 World-space vs local-space

| Effect | Space |
| --- | --- |
| Hand charge, forearm ribbon during swing | Local (socket) |
| Ground sweep, Flame Wave, Force Pulse, impacts, embers, brace | World |
| Projectile body | Follows `Projectile` transform (already) |
| Trails on projectile | Local to projectile |

Favour **duplicating** pack prefabs into Threefold-owned paths (proposal):  
`Assets/Threefold/Art/VFX/{Arcane,Flame,Aegis,Shared}/`  
Never edit third-party source prefabs in place.

### Adaptation checklist (all candidates)

1. **Colour:** pull HDR multipliers to ≤ ~1.2; use proposed discipline accents (desaturated).  
2. **Particle count:** target Disciplines budget (≈ 6–18 for bursts; slash mesh may be 1 mesh + ≤ 8 soft particles).  
3. **Remove:** Point Lights, LightsModule, CollisionModule, AudioSources on combat FX (SFX via separate system later).  
4. **Remove / disable:** heat haze, DistortionPoint, parallax occlusion decals on mobile default.  
5. **Lifetime:** match swing start-up / impact brevity (0.25–0.6 s typical).  
6. **Materials:** Hovl → URP Particles/Unlit (or approved soft unlit graph); prefer soft alpha over additive stack spam.  
7. **Scale:** readable at third-person mobile distance; no screen-filling radii.  
8. **Shape over noise:** keep mesh slash / shockwave ring; drop dense spark storms.  
9. **Texture memory:** Free Slash Android max 512–1024; confirm Hovl/Vefects 256–512.  
10. **Quality tiers:** Performance drops secondary particles and trails; Balanced = adapted default; Quality may allow slightly longer trails — **same silhouette in all three**.

## F. Performance assessment

**No effect in this audit has been profiled.** Findings are structural risk from prefab YAML + project docs.

### Likely bottlenecks

| Risk | Evidence | Mitigation |
| --- | --- | --- |
| Transparent overdraw | Multi-PS additive stacks; MobilePerformance already flags bursts + telegraphs | Fewer layers; smaller particles; Performance tier strips secondaries |
| Particle counts | Stock `maxParticles` 1000 per system × 4–9 systems | Cap to burst size; `BurstParticleShare` for multi-hit |
| Extra lights | Free Slash Point Light; Vefects LightsModule | Delete from adapted prefabs |
| Collision module | Free Slash slashes/projectiles; some Hovl sparks | Disable — gameplay hits already resolved in C# |
| Shader cost | Custom graphs + Amplify fire | Prefer Unlit; test Free Slash on device before widespread use |
| Texture memory | Free Slash default 2048 | Android overrides 512/1024 |
| Distortion | Vefects haze; Hovl DistortionPoint; opaque texture off | Do not enable opaque texture only for FX |
| Audio on VFX prefabs | Vefects AudioSources | Remove from visual prefabs |
| Draw calls / variants | Material proliferation across packs | Shared Threefold VFX materials per discipline |
| VFX Graph | N/A — not installed | Stay on Particle System |

| Preset | FX behaviour |
| --- | --- |

| Balanced (60) | Adapted defaults |
| Quality (60) | Slightly richer trails / secondary sparks; still no lights/distortion |

Wire FX density to `GraphicsPresets` / `VisualStyleController` quality level later — do not fork combat logic.

## I. Recommended first implementation

### Choice: Arcane melee step 1 (slash + impact)

**Why this slice**

1. Free Slash is already URP Shader Graph — fewest pipeline blockers.  
2. Exercises the real combat event path (`SwingStarted` → `SwingLanded`) without charged aiming complexity.  
3. Establishes the adapt-don’t-edit-pack workflow and pooling integration.  
4. Arcane’s thin ribbon is the hardest identity test for Soft Illustrated Realism; if Water/default slash can be calmed to fit the Art Bible, Flame/Aegis adaptations are clearer.  
5. Does not depend on missing melee animations if the slash is oriented from swing direction at hip/chest height initially (hand sockets optional stretch goal).

### Sequence

1. Duplicate `Slash Water VFX` → `Art/VFX/Arcane/ArcaneMeleeSlash.prefab`; strip light/collision; cut particle children; desaturate.  
2. Duplicate `Impact` → `ArcaneMeleeImpact.prefab`; budget ~10 particles.  
3. Add `meleeSwingEffect` to presentation (or temporarily replace sweep-only feel by spawning slash alongside existing sweep).  
4. `DisciplineFeedback.HandleSwingStarted` spawns slash; `HandleSwingLanded` keeps impact spawn.  
5. Owner reviews in Editor on Discipline Range; iterate colour/scale before Flame/Aegis.

### Explicit non-goals for the slice

- No combat timing changes  
- No third-party prefab edits  
- No VFX Graph  
- No enabling URP opaque texture  
- No Flame/Aegis wiring yet

## Proposed integration architecture

```
DisciplineDefinition (ScriptableObject)
  └─ DisciplinePresentation  →  prefab refs only (Threefold-owned adapted PooledObjects)
DisciplineCombat (rules carry-out)  →  events only
DisciplineFeedback (presentation)  →  Pools.Spawn / socket attach / stop on interrupt
ChargedProjectileDefinition / ChargedAreaDefinition  →  projectile & impact prefab refs
PropertyStateVisuals  →  world reaction FX (embers, brace, charge) — unchanged API
Graphics quality level  →  optional particle share / secondary enable
```

Principles:

- Data-driven refs on existing SOs; **no pack paths in gameplay code**.  
- Rules stay plain C#; presentation listens.  
- Pool everything; one-shot by default.  
- Replace placeholders by filling empty references in setup commands (idempotent).  
- Future disciplines/effects = new adapted prefabs + SO fields, not combat forks.
